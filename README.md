# Claude Auto Flow

Claude Code用の自律ワークフロー・オーケストレータースキルです。「検討 → 計画 → 実装 → チェック&プッシュ」の一連の流れを、ユーザーへの確認なしに最後まで自動進行させます。

## 概要

`auto-flow` は以下のパイプラインを完全自律で実行するオーケストレータースキルです。

```
[調査(任意)] → 検討 → 計画 → 実装 → セキュリティチェック & プッシュ
   Haiku    Opus/Fable Sonnet/Opus Sonnet      Haiku
```

- 各フェーズはサブエージェントとして起動され、前フェーズの成果物が次フェーズに引き継がれる
- 各スキルに組み込まれた承認ゲート（「実装してください」待ち、プッシュ前確認など）は、本フロー内ではすべて自動承認として扱われる
- 唯一の停止条件は、セキュリティチェックで問題が検出された場合のみ

## 依存関係

このスキルは単体では動作しません。以下のリポジトリで公開されている5つのスキルを事前に `~/.claude/skills/` に配置しておく必要があります。

**[rapyutapazoo-design/claude-skills](https://github.com/rapyutapazoo-design/claude-skills)**

- `consultant-mode` — 検討フェーズ
- `plan-creator` — 計画フェーズ
- `researcher` — 調査フェーズ（任意）
- `safe-push` — チェック&プッシュフェーズ
- `git-workflow` — 単体利用のみ（auto-flow内では使用しない）

先に上記リポジトリの内容を `~/.claude/skills/` 配下に配置してから、本スキルをインストールしてください。

## インストール手順

```bash
mkdir -p ~/.claude/skills/auto-flow
cp SKILL.md ~/.claude/skills/auto-flow/
```

## 使い方

以下のいずれかのトリガーフレーズを含むメッセージを送ると起動します。

- 「オートフロー」
- 「auto-flow」
- 「自律実行して」
- 「自動で最後まで進めて」
- 「全自動で進めて」

### 調査フェーズを追加する場合

課題文に以下のいずれかを含めると、冒頭に調査（researcher）フェーズが追加されます。

- 「--research」
- 「調査込みで」

## モデル配分表（フェーズ別・動的選択）

各フェーズは、コストが最小になるモデルを割り当てたサブエージェントで実行されます。検討・計画の2フェーズは、課題の難易度・実装規模に応じてフェーズごとに独立してモデルを昇格させる動的選択方式です（デフォルトはトークン消費が少ない方を優先）。

| フェーズ | モデル | 昇格条件 |
|---------|--------|---------|
| 調査（任意） | Haiku | 固定 |
| 検討 | Opus（既定）／ Fable 5（難タスク時） | 5基準中2項目以上該当で Fable 5 へ昇格 |
| 計画 | Sonnet（既定）／ Opus（複雑時） | 4基準中2項目以上該当で Opus へ昇格 |
| 実装 | Sonnet | 固定 |
| チェック & プッシュ | Haiku | 固定 |

**検討フェーズの昇格基準（5項目）:** ① 設計空間が広い ② 複数システム・技術の横断 ③ 要件が曖昧で前提設定が必要 ④ 新規アーキテクチャ設計 ⑤ 相反するトレードオフが3つ以上。Fable 5 が利用不可の環境では Opus に自動フォールバックします。

**計画フェーズの昇格基準（4項目）:** ① 実装ステップ見込みが多い（目安: 対象ファイル5以上またはステップ8以上）② コンポーネント間の依存順序が複雑 ③ 破壊的変更・データ移行を含む ④ 採用案に未確定の技術判断が残っている。

### モデルオーバーライド

起動メッセージに以下を含めると、両フェーズのモデルを一括で固定できます。

- 「--economy」「節約モードで」 → 検討=Opus・計画=Sonnet に固定（コスト優先）
- 「--fable」「最高品質で」 → 検討=Fable 5・計画=Opus に固定（品質優先）

選択されたモデルと判定根拠は開始宣言に、実際に使用したモデルは完了報告のモデル列に記録されます。

> **設計意図:** 検討は方向を決める回復不能な工程のため品質の床を Opus に保ちつつ難タスク時のみ Fable 5 へ昇格、計画は構造化作業で実装エージェントの裁量により部分回復が可能なため Sonnet まで下げられる、という非対称2択です。この方式によりデフォルト構成（検討=Opus／計画=Sonnet）は従来（検討・計画とも Opus 固定）よりコストが下がります。

## 唯一の停止条件

safe-push のセキュリティチェックで 🔴（シークレット漏洩・除外ファイル混入）が検出された場合のみ、プッシュせずに停止しユーザーへ報告します。それ以外（🟡注意・🟢問題なし）は自動承認で続行し、最後まで自律的に完了します。
